LLM Council · 2026-11-25

Should the rootfile architecture be committed to, and how should it be changed so that errors fail at compile time?

A Rust reader and writer for CERN ROOT files: TFile, streamed objects, TTree, RNTuple. Five advisors reviewed ARCHITECTURE.md against ROOT-BEHAVIOUR.md, which lists ROOT's verified on-disk behaviour. Five anonymous peer reviewers then ranked them, and a chairman wrote the verdict.

Verdict: commit to the layering, rewrite the API surface first

The sans-IO core, the ReadAt/AsyncReadAt split, the separate File and WritableFile types, and DynObject as the run-time path all hold up. But ARCHITECTURE.md contradicts ROOT's real behaviour in five places, and its compile-time claims are thin. Fix both before any semver commitment.

The write API: a scoped closure, not per-writer &mut borrows

rootfile::create("out.root", |f| {           // f: &FileScope<'s>
    let mut ev   = f.tree::<Event>("Events")?;  // TreeWriter<'s>
    let mut runs = f.tree_dyn("Runs", schema)?;
    let mut nt   = f.ntuple("Hits", model)?;
    for e in src { ev.fill(&e)?; if cond { f.put("h_pt", &hist)?; } }
    Ok(())
})?;  // children finished, then keys, StreamerInfo, header: always, with a Result
  • Several trees, ntuples and histograms can be written at once, which is ROOT's usual pattern. The borrow checker still guarantees that no handle outlives the file, as with std::thread::scope.
  • Finalization cannot be forgotten. Drop never does I/O. The owned WritableFile remains for long-lived use, and its close(self) returns an error while children are still open.
  • Format rules go into types:
    • RBuffer::new(bytes, origin)
    • Record::KEY_FORM, with values AlwaysLarge or ByPosition
    • newtypes for versions, cycles, offsets and lengths
    • WBuffer::object(version, |w| …)
    • derive checks at macro expansion, guarded by trybuild tests
  • What the compiler cannot see is caught by tests: whether ROOT can read the output, and whether real files are read correctly.
The one thing to do first Move the ROOT/uproot cross-check into M0. Write an empty file and a one-histogram file, run them through ROOT's TFile::Recover, ROOT's TFile::Open and uproot, and gate CI on the result before any other writer code.

Where the council clashed

  • Key size form. Three advisors wanted KeyHeader<Small|Large>. Ordinary keys switch to 8-byte offsets only when they sit past kStartBigFile, which is known only at run time. Only baskets and RBlob are fixed by kind, so a type parameter would encode some keys wrong.
  • Per-writer &mut borrows. Three advisors proposed them; reviewers showed they forbid filling two trees at once, or writing a histogram while a tree is open.
  • Scope. The Expansionist's build-time schema macro only checks one reference file, and its enum const generics are unstable Rust. Both were rejected.

Blind spots only the peer review caught

  • #[must_use] does not force close(). Rust has no linear types; only closure scoping guarantees finalization.
  • AsyncReadAt requires Send futures, but browser fetch futures are not Send. WASM needs a LocalAsyncReadAt.
  • Arrow, object_store and bytes types in the public API would force a semver break with every Arrow major release. Move them to adapter crates.
  • Sealed traits and trybuild compile-fail tests are missing.
  • Porting TClass::GetCheckSum and copying ROOT's streamer infos (LGPL) needs a licence review.

Advisor responses

The Contrarian Don't commit yet

Several sections contradict ROOT-BEHAVIOUR.md, and the compile-time claim rests on one type split.

  • RBuffer has no origin, so back-references and basket entry offsets resolve to the wrong byte.
  • "Fail loudly" rejects files ROOT opens, because ROOT repositions after a byte-count mismatch.
  • The allocator is first-fit where ROOT uses best-fit, writes no gap markers, and has no initial free segment.
  • The key size form is chosen by the wrong rule, and bare rntuple files can't pass through File::open.
  • update(true) can't have one return type. Child writers should borrow the file. Drop doing I/O makes half-written files look valid. Invalid compression levels and versions can be constructed.
  • No crate holds the code that tree and ntuple share.
The First Principles Thinker Ranked strongest

The goal is framed wrongly. "ROOT can't read what we wrote" and "we misread a real file" are run-time facts that only the corpus and the cross-checks can catch. Aim compile-time effort at the writer API and the derive macro.

  • Commit to the layering.
  • Fix the RBuffer origin.
  • Use trait Record { const KEY_FORM }, not a const-generic Seek.
  • Compress only when ObjLen is over 256 bytes.
  • Make byte counts lenient by default.
  • Readers follow pointers, not class names.
  • Writer handles are borrowed, consumed and #[must_use], with no close in Drop.
  • Add open_update().
  • Add derive checks at expansion and unify the version types.
  • Don't commit to writing TTrees until their members are verified.
The Expansionist Biggest blind spot
  • Commit, and make the schema system the centre: an "sqlx for ROOT" macro, root_schema!("ref.root", "Events"), that generates typed structs at build time.
  • One RootSchema trait shared by derived and run-time schemas, with typed projections.
  • Typestate for key forms, and const-generic compression.
  • Bare RNTuple as a lakehouse format, with DataFusion and Polars integrations.
  • Python bindings at M2.
The Outsider Merge the documents first
  • The two documents disagree: on fail loudly vs lenient, first-fit vs best-fit, 4 KiB vs 300 bytes, and on the rules that are missing.
  • One concept has several types: the class version is i16 in one place and i32 in others. Add newtypes ClassVersion, Cycle, FileOffset, ByteLen and KeyRelOffset.
  • The compile-time claims are thin: the update(true) flag, a public compression level, an unchecked count = "n" string, the close in Drop.
  • The jargon needs a glossary.
  • Make ObjectPath and Cycle real types instead of strings.
The Executor Commit after a week
  • Settle the writer's claimed ROOT version and verify the TTree members.
  • Write the ROOT corner cases into the architecture.
  • Publish only the facade crate. The organizer noted this can't work as stated: a published crate cannot depend on unpublished crates.
  • Move the cross-check to M0.
  • Compile-time changes, cheapest first: the WBuffer::object closure, key-kind markers, a consuming close, a const-checked Compression, derive checks.
  • Typed access is a layer over the dynamic path.
Peer review highlights 5 reviewers, shuffled labels
  • Reviewer 1: First Principles strongest, Contrarian second. Arrow types in the public API mean semver breaks. LGPL questions about the checksum port and the copied streamer infos.
  • Reviewer 2: Checked the Rust claims. A "guard that must be consumed" doesn't exist in Rust, enum const generics are unstable, and #[must_use] does not force close. Closure scoping is the only real guarantee. Per-writer &mut blocks concurrent trees.
  • Reviewer 3: A type-parameter key form would encode ordinary keys wrong. Const-generic compression blocks the run-time choice cp needs. Send futures contradict the WASM goal.
  • Reviewer 4: Users fill Events, Runs and Lumi trees side by side. Use a scoped API or a shared sink. Add trybuild compile-fail tests.
  • Reviewer 5: Semver hygiene: sealed traits, and keeping fast-moving dependencies out of the stable facade.
